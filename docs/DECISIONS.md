# DECISIONS — принятые решения

| Дата | Решение | Почему |
|---|---|---|
| 18.10.2026 | Версия Godot — **4.7.2 stable** | Уже скачана у владельца, это актуальная стабильная версия |
| 18.10.2026 | Python 3.12 для `enginectl` | Уже установлен и прописан в PATH |
| 18.10.2026 | Код хранится в открытом репозитории krasking94/GodotAI | Решение владельца. Следствие: никаких секретов в репозитории |
| 19.10.2026 (план v2) | Сначала плагин к обычному Godot, форк — позже | Сборка Godot из исходников долгая; первый результат нужен быстро (см. PLAN.md, раздел 4) |
| 19.10.2026 | Игра запускается отдельным процессом Godot, а не кнопкой «Запустить» в редакторе | Так весь вывод игры попадает в файл лога, и ИИ читает его командой `log get` |
| 19.10.2026 | «Одной фразой» = фраза человека → ИИ пишет JSON-описание сцены → одна команда `scene build`. Языковая модель внутри enginectl не живёт | ИИ (Claude и другие) остаётся снаружи, как задумано в плане; enginectl и плагин — простые проверяемые инструменты без ключей и сети |
| 19.10.2026 | Персонаж — от первого лица, управление читается прямо с клавиш (W A S D, стрелки, пробел, мышь) без карты действий Godot | Карту действий пришлось бы править в project.godot отдельной командой; для первой версии проще и прозрачнее. Переход на карту действий (нужна для экранного управления на Android) — позже |
| 19.10.2026 | Машина — на встроенном VehicleBody3D, а не на своей физике | Из коробки едет, рулит и тормозит, описывается теми же операциями моста. Известные ограничения (нет предела скорости, может перевернуться) пока не мешают демо; свою физику писать только если упрёмся |
| 19.10.2026 | У игровых объектов есть режим самопроверки (`test_drive`/`test_program` у машины, отчёт «на полу» у персонажа), который печатает измерения в лог | ИИ не видит экран, но видит лог: так он проверяет физику и управление заездами без человека и ловит ошибки вроде переворота или падения с края до живой проверки |
| 19.10.2026 | Тест-программы объектов задаются командой `game run --test кто=программа`, а не записываются в сцену | Человек, запуская сцену, сразу получает управление; ИИ проверяет ту же сцену автозаездом без правки файла. Godot отдаёт всё после `--` скриптам через `OS.get_cmdline_user_args()` |
| 19.10.2026 | Разметка земли — шейдером по мировым координатам (`game/grid.gdshader`), а не текстурой | Без картинок и импорта, одинаковая клетка на плоскости любого размера; движение и повороты видны. Перёд машины обозначается формой (кабина ближе к переду, фары и стоп-сигналы), иначе глаз читает машину задом наперёд |
| 19.10.2026 | Выход из машины — по четырём точкам (двери, зад, перёд) с проверкой земли лучом и свободного места капсулой персонажа | Простая и предсказуемая проверка «нельзя выйти в стену» средствами физики Godot; если все четыре заняты, персонаж остаётся в машине и об этом печатается строка, которую видит ИИ |
| 19.10.2026 | Плагин перечитывает скрипт с диска при подключении по `res://` | Редактор без фокуса не замечает внешних правок файла; иначе ИИ, добавив `@export`, получает «нет свойства» при сборке сцены |
| 19.10.2026 | Снимок экрана делает отдельный процесс игры (`game screenshot` + `game/screenshot.gd`), а не плагин редактора | В кадре то, что видит игрок; не нужен открытый редактор; в облаке работает через виртуальный экран. Снимок вьюпорта редактора — возможное дополнение |
| 19.10.2026 | Повторяющиеся объекты — отдельные сцены и операция `instance`, а не копии описаний | Машина описана один раз (`car.json` → `car.tscn`), двор и площадка вставляют её; правка машины обновляет все сцены. Свойства задаются корню экземпляра |
| 19.10.2026 | Перезапись открытой сцены защищена: отказ при несохранённых правках, резервная копия состояния вкладки при любой перезаписи | Выполняет обязательную проверку №3 плана без публичного API «сцена изменена» (читаем «(*)» в заголовках вкладок); копии в `.godot/ai_bridge/backup/`, 20 последних |
| 19.10.2026 | Внешние правки файлов подхватываются командой `project refresh`, а не ожиданием фокуса окна | Редактор без фокуса не замечает правок ИИ и `git pull`; команда перечитывает скрипты и открытые сцены с диска, несохранённые сцены не трогает |
| 19.10.2026 | Папка `tools/` закрыта от редактора файлом `.gdignore` | Там Python и примеры, Godot их компилировать не должен (учебный сломанный скрипт давал красные ошибки при открытии проекта) |
| 19.10.2026 | Взаимодействие по E — через группу `interactables` и два метода у предмета: `prompt()` и `interact(player)` | Персонаж не знает типов предметов: дверь, кнопка, ключ и машина добавляются одним скриптом с двумя функциями, подсказка внизу берётся из `prompt()`. Новый вид предмета не требует правки персонажа |
| 19.10.2026 | Перенос персонажа (выход из машины, возврат при падении) выключает его столкновения на два кадра физики | Движок считает перенос кинематического тела движением за один кадр: персонаж «пролетал» сквозь машину и отбрасывал её со скоростью 40 м/с под пол. Два кадра без столкновений стоят 3 мм падения и незаметны |
| 19.10.2026 | Упавшая ниже −10 м машина (и персонаж) возвращается на стартовое место; двор обнесён стенами с четырёх сторон | Отзыв владельца: уехал за край и падал без конца. Стены не дают уехать, возврат страхует на открытых площадках вроде `car_test` |
| 19.10.2026 | В `scene build` свойства корня (`set` по пути `.`) применяются сразу при планировании | Корень новой сцены ещё не в дереве, откатывать нечего; так `script` и его `@export`-поля задаются одной операцией, иначе проверка «есть ли свойство» шла до подключения скрипта |
| 19.10.2026 | Сохранение — JSON из `save_state()` узлов группы `persist`, ключ записи — путь узла от корня сцены | Любой объект сохраняется двумя функциями без правки общего кода (как `prompt()`/`interact()` у предметов); JSON читается человеком и ИИ, по нему легко проверять, что записалось |
| 19.10.2026 | Запись сохранения: временный файл → чтение обратно → прежняя копия в `save.bak.json` → переименование | Сбой на записи или испорченный файл никогда не уничтожают последнюю рабочую копию (проверка №6 плана); при загрузке испорченного файла игра печатает причину, продолжается и берёт прежнюю копию |
| 19.10.2026 | Меню паузы строится кодом в одном узле CanvasLayer, а не описывается в сцене | Четыре кнопки и подпись не стоят десятка узлов Control в JSON; `process_mode = ALWAYS` и `get_tree().paused` останавливают весь мир, а Esc перехватывается до персонажа |
| 19.10.2026 | Готовые модели берутся из стартовых наборов Kenney на GitHub, а не с kenney.nl | Сайт закрыт сетевой политикой облака, GitHub доступен; модели те же (CC0), лицензии лежат рядом в `assets/kenney/` |
| 19.10.2026 | Модель машины вставляется операцией `instance` узлом `Model`, а физика подстраивается под неё скриптом (`_fit_model`), а не описывается вручную | Описание сцены остаётся «поставь модель»; колёса VehicleWheel3D встают на место колёс модели, радиус и форма кузова берутся из геометрии. Другая модель Kenney с теми же именами детей (`body`, `wheel-…`) работает без правок |
| 19.10.2026 | Декорации из моделей стоят за стенами двора, без столкновений | У импортированных `.glb` нет физических форм; снаружи они видны поверх стен и не мешают. Столкновения для моделей внутри двора — следующий срез |
| 19.10.2026 | Твёрдость модели — скрипт `prop.gd` на корне экземпляра, формы строятся по мешам при запуске (`create_trimesh_collision`) | Точные формы без ручной разметки и без правки плагина; коробка по AABB перекрывала бы всю плитку Kenney. Описание сцены говорит только «эта модель твёрдая» |
| 19.10.2026 | Клавиши заменены картой действий: таблица в `game/actions.gd`, копия в `project.godot`, скрипты читают действия | Одно место для всех клавиш; экранные кнопки, геймпад и клавиатура «нажимают действие», игровой код их не различает. `ensure()` страхует, если настройки проекта не перезагружены |
| 19.10.2026 | Экранное управление отправляет нажатия как события (`parse_input_event(InputEventAction)`), а не `Input.action_press` | `action_press` только меняет состояние: опрос видит, а обработчики событий (E, пауза, F5) — нет. События проходят оба пути, как настоящая клавиша |
| 19.10.2026 | Панель экранного управления рисуется кодом в одном CanvasLayer и включается по признаку сенсорного экрана или `--touch` | На компьютере не мешает, на телефоне появляется сама; снимок и проверка без телефона — через `--test touch=` |
| 19.10.2026 | Сборка игры — отдельным процессом `Godot --headless --export-*` из enginectl, а не через плагин | Так же, как запуск игры: работает при закрытом редакторе, весь вывод в лог, редактор не блокируется. Плагин при этом в пакетном процессе молчит (0.9.2), иначе он затирал файл подключения настоящего редактора |
| 19.10.2026 | `export_presets.cfg` вне репозитория, в репозитории пример `tools/export_presets.example.cfg`, из которого файл создаётся сам | В настоящем файле будут пути к ключам подписи; пример даёт одинаковые пресеты всем и не хранит секретов |
| 19.10.2026 | Windows-сборка одним файлом (`embed_pck`), без смены значка (`modify_resources=false`) | Владельцу проще один `.exe`; значок потребовал бы `rcedit`, отложено |
| 19.10.2026 | Android-окружение (JDK 17, Android SDK, шаблон) ставит владелец на своём компьютере, в облаке не ставится | dl.google.com и adoptium.net закрыты сетевой политикой облака; телефон для проверки тоже у владельца |
| 19.10.2026 | Отмена задачи ИИ не удаляет файлы, а переносит их в `.godot/ai_bridge/trash`; историю сцены откатывает только если сверху её же действие (в имени действия номер записи журнала) | Ручные правки человека важнее: их отмена без спроса недопустима, а удалённый файл не вернуть |
| 19.10.2026 | Панель «Задачи ИИ» — обычный dock плагина рядом с Инспектором, без форка редактора | Этап D не потребовал ядра: dock, Tree и RichTextLabel дают всё нужное; форк остаётся на этап E |
| 19.10.2026 | `scene.inspect` в журнал не пишется | Чтение не меняет проект, а записей от него больше, чем от всего остального |
| 19.10.2026 | Мост ставится в другой проект копированием файлов (`enginectl setup`), а не как отдельный пакет или git-подмодуль | Владелец не программист: одна команда и никаких зависимостей; плагин — два файла |
| 19.10.2026 | 2D-пример читает встроенные действия `ui_left/ui_right/ui_accept`, а не карту действий демо | Пример должен работать в чистом проекте без `game/actions.gd`; карта действий — часть 3D-демо с телефоном |
