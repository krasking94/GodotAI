# AI_PROTOCOL — команды моста

Описание формата команд `enginectl` ↔ плагин `ai_bridge`.

## Подключение

- Плагин слушает только `127.0.0.1`, порт 47615 (если занят — следующие до 47624).
- При включении плагин создаёт случайный токен и пишет `{host, port, token, pid}` в `.godot/ai_bridge/connection.json` (папка `.godot` не попадает в Git).
- Обмен: одна строка JSON на запрос, одна строка JSON на ответ.
- Запрос: `{"token": "...", "command": "doctor", "args": {}}`.
- Неверный токен — ответ с `status: "error"`.

Запуск: `python tools/enginectl/enginectl.py doctor` из папки проекта (на Windows при необходимости `py -3`).

Самопроверка плагина без enginectl: `Godot --headless --path <проект> --editor -- --ai-bridge-selftest`. Плагин подключается к своему порту, шлёт `doctor` с верным и с неверным токеном, печатает оба ответа и `AI Bridge selftest: PASS`/`FAIL`, затем закрывает редактор с кодом 0/1.

Каждый ответ содержит: `status`, `result`, `errors`, `warnings`, `files`.

| Команда | Статус |
|---|---|
| `doctor` | проверена 19.10.2026: версия Godot и плагина, имя и путь проекта, открытая сцена |
| `scene inspect` | проверена 19.10.2026 (команда протокола `scene.inspect`, args: `path` — узел, с которого начать, по умолчанию корень; `depth` — глубина, -1 = все). Ответ: `scene_path`, `node_count`, `root` — дерево узлов, у каждого `name`, `type`, `path`, `children`, при наличии `script`, `instance`, для Node3D/Node2D `position`, `rotation_degrees`, `scale`, для Control `position`, `size` |
| `scene apply` | проверена 19.10.2026 в headless-редакторе (команда `scene.apply`, args: `ops` — список операций, `dry_run`). Операции: `create` (parent, name, type, props), `set` (path, props), `delete` (path). Сначала проверяются все операции, при любой ошибке не применяется ничего. `parent` и `path` — всегда путь от корня сцены: для узла внутри только что созданного `Car` пишется `"parent": "Car/WheelFL"`, а не `"WheelFL"`. Применение — одно действие Undo/Redo редактора (Ctrl+Z отменяет весь набор). Ответ: `plan` (что создано/изменено/удалено, для set — старое и новое значение), `applied`, `dry_run`. Операция `instance` (плагин 0.9.0): `{"op": "instance", "parent": ".", "name": "Car", "scene": "res://scenes/car.tscn", "props": {...}}` вставляет готовую сцену как узел; `props` задаются корню экземпляра (позиция, поворот, `@export`-поля его скрипта), внутренние узлы остаются в своей сцене, и `set` по ним не сохраняется; сцена не может содержать саму себя |
| `scene save` | проверена (`scene.save`): сохраняет открытую сцену, путь в `files` |
| `scene open` | проверена (`scene.open`, args: `path`): открывает существующую сцену в редакторе |
| `scene undo` / `scene redo` | проверены (`scene.undo`, `scene.redo`): отмена/повтор последнего действия в истории открытой сцены, как Ctrl+Z / Ctrl+Y; в ответе имя действия |
| `scene new` | проверена (`scene.new`, args: `path`, `root_type`=Node3D, `root_name`): создаёт сцену с одним корнем, сохраняет и открывает в редакторе |
| `scene build` | проверена 19.10.2026 headless (`scene.build`, args: `path`, `root_type`, `root_name`, `ops` — только `create` и `set`, `overwrite`=false, `open`=true, `main_scene`=false). Собирает новую сцену в памяти и сохраняет одним шагом; при любой ошибке файл не создаётся. Ответ: `node_count`, `reread_node_count` (файл прочитан обратно с диска), `plan`, `opened`, `main_scene`, в `files` путь сцены (и `res://project.godot`, если назначена главной). В enginectl: `scene build --file описание.json` (поля `scene {path, root_type, root_name}` и `ops`; `--path`, `--root-type`, `--root-name` важнее полей файла), `--ops '[...]'` + `--path`, флаги `--overwrite`, `--main`, `--no-open`. С 0.9.1 `set` по пути `.` (корень собираемой сцены) применяется сразу, поэтому `script` и `@export`-поля этого скрипта можно задать одной операцией (`{"script": "res://game/item.gd", "item_name": "Ключ"}`). С 0.9.0: `instance` допустим и здесь (сцена читается с диска, а не из кэша, поэтому можно собрать `car.tscn` и сразу вставить её в `yard.tscn`); при `overwrite` открытой сцены вкладка всегда перезагружается с диска, а если в ней есть несохранённые изменения, команда отказывает (`--force` перезаписывает); при любой перезаписи открытой сцены её текущее состояние (как в редакторе) копируется в `.godot/ai_bridge/backup/<имя>_<дата>.tscn` (хранятся 20 последних), путь в ответе `backup`. Несохранённость определяется по заголовкам вкладок «(*)», публичного API у редактора нет |
| `script set` | проверена (`script.set`, args: `path`, `content`, `node` необязательно): записывает .gd, обновляет его в редакторе, при `node` вешает на узел через Undo/Redo. Если скрипт не компилируется, в ответе `parse_error` и предупреждение |
| `game run / stop / status` | проверены. Реализованы в enginectl, не в плагине: игра запускается отдельным процессом Godot (путь берётся из connection.json открытого редактора, из `--godot` или `GODOT_EXE`; на Windows автоматически берётся `_console.exe`), вывод пишется в `.godot/ai_bridge/last_run.log`. `run` ждёт `--seconds` (по умолчанию 8) и останавливает игру, либо `--background`; `--scene` выбирает сцену, иначе главная; `--headless` без окна; `--test кто=программа` (можно несколько) передаёт игре аргументы `--test-кто=программа` после `--`, скрипты читают их через `OS.get_cmdline_user_args()` и выполняют самопроверку (например `--test car=gas:2,left:1,brake:1`), поэтому сценам не нужны записанные в них тест-программы |
| `game screenshot` | проверен в облаке. Реализован в enginectl: запускает Godot отдельным процессом со скриптом `game/screenshot.gd` (`extends SceneTree`: грузит `--shot-scene` или главную сцену, через `--shot-after` секунд сохраняет `root.get_texture().get_image()` в `--shot-out`). Параметры: `--scene`, `--out` (по умолчанию `.godot/ai_bridge/screenshot.png`), `--after` (сек, по умолчанию 2), `--size` (1280x720), `--test кто=программа`, `--godot`. Ответ: `path`, `width`, `height`, `virtual_display`, `output` игры, `errors_in_game`; лог в `.godot/ai_bridge/screenshot.log`. Нужно окно: на Linux без `DISPLAY` команда оборачивает запуск в `xvfb-run` и включает `opengl3`/`gl_compatibility` (программный рендер llvmpipe); шум виртуального экрана (ALSA, V-Sync) из ошибок вычищается |
| `log get` | проверена: разбирает лог последнего запуска на `errors` (SCRIPT ERROR / ERROR / USER ERROR с подробностями `at:`), `warnings` и `output` |
| `screenshot` | не реализована |
| `project main-scene` | проверена (`project.main_scene`, args: `path`): назначает главную сцену, сохраняет project.godot |
| `project refresh` | проверена 19.10.2026 headless (`project.refresh`, args: `files` — список res://, `reload_scenes`=true). Подхватывает правки файлов, сделанные снаружи, пока окно редактора без фокуса (ИИ правит скрипт, `git pull`): сканирует файловую систему, сверяет с диском скрипты узлов открытых сцен и перечитывает изменившиеся (ответ `reloaded_scripts`), перечитывает файлы из `--file` из кэша (`reloaded_files`), перезагружает с диска открытые сцены без несохранённых изменений (`reloaded_scenes`, несохранённые в `skipped_unsaved`). В enginectl: `project refresh [--file res://…]… [--no-scenes]` |
| `project export` | проверена 19.10.2026 в облаке (Linux и Windows). Реализована в enginectl, не в плагине: запускает `Godot --headless --path <проект> --export-debug|--export-release <пресет> <файл>` отдельным процессом. Аргументы: `--preset` (имя из `export_presets.cfg`; файл создаётся из `tools/export_presets.example.cfg`, если его нет), `--out` (по умолчанию `export_path` пресета), `--release`, `--list`, `--timeout`, `--godot`. Перед запуском проверяет, что для версии Godot (`Godot --version`) установлен нужный файл шаблона (`windows_debug_x86_64.exe`, `linux_release.x86_64`, `android_debug.apk`…) в папке шаблонов, иначе объясняет, где их скачать. Ответ: `path`, `size_mb`, `duration`, `exit_code`, `log_path` (`.godot/ai_bridge/export.log`), `output` без строк прогресса, `errors` из лога Godot. Плагин 0.9.2 в таком пакетном процессе (`--export-*`, `--import`, `--quit-after`…) сервер не запускает и `connection.json` открытого редактора не трогает. |

## Значения свойств в `scene apply`

- Числа, строки, `true`/`false` — как есть.
- Список из 3 чисел → Vector3 (`position`, `rotation_degrees`, `scale`), из 2 чисел → Vector2.
- Цвет: `"#rrggbb"` или список из 3–4 чисел от 0 до 1.
- `"res://путь"` → загружается ресурс (меш, материал, сцена). Для скрипта текст сверяется с диском и при расхождении перезагружается: редактор без фокуса не замечает правок, сделанных снаружи, и иначе отдаёт из кэша старую версию без новых `@export`-свойств (ошибка вида «у CharacterBody3D нет свойства …»).
- `mesh`: `{"primitive": "box"|"plane"|"sphere"|"cylinder"|"capsule", "size": [...], "radius": r, "height": h, "color": ...}`. Вместо `color` можно задать `"shader": "res://game/grid.gdshader", "params": {...}` → ShaderMaterial (цвета в `params` как `"#rrggbb"`, списки чисел → Vector2/Vector3); `game/grid.gdshader` рисует клетчатую разметку по мировым координатам (плагин 0.8.0).
- `material_override`: `{"color": ...}` → StandardMaterial3D, либо `{"shader": ..., "params": {...}}` → ShaderMaterial.
- `shape` (у CollisionShape3D): `{"primitive": "box"|"sphere"|"capsule"|"cylinder", "size": [x, y, z], "radius": r, "height": h}` → BoxShape3D, SphereShape3D, CapsuleShape3D, CylinderShape3D.
- `environment` (у WorldEnvironment): `{"sky": true, "sky_color": ..., "horizon_color": ..., "ground_color": ..., "ambient_energy": 0.8, "fog": false}` → Environment с процедурным небом и рассеянным светом от неба. Без него теневые стороны объектов чёрные. Физика в Godot: видимый меш и невидимая форма столкновения — разные узлы, поэтому пол делается как StaticBody3D с детьми MeshInstance3D и CollisionShape3D, персонаж — CharacterBody3D с CollisionShape3D и Camera3D (пример: `examples/yard.json`).

В `plan` для мешей показываются тип, размер и цвет (`{"mesh": "BoxMesh", "size": [...], "color": [...]}`).

Примеры описаний: `tools/enginectl/examples/car.json` (машина как отдельная сцена `scenes/car.tscn`: корень VehicleBody3D, форма столкновений, модель Kenney узлом `Model`, четыре VehicleWheel3D; свойства корня через `set` по пути `.`; `car.gd` подгоняет колёса и форму под модель при запуске), `yard.json` (двор с физикой: поле 30×30, стены по периметру, сарай, свет, персонаж; машина, дверь, ключ и кнопка через `instance`), `car_test.json` (площадка с разметкой, ориентирами и той же машиной через `instance`; в обеих сценах узлы SaveManager, PauseMenu и TouchControls со скриптами `game/save_manager.gd`, `game/pause_menu.gd`, `game/touch_controls.gd`), `door.json`, `button.json`, `key.json` (дверь, кнопка, ключ: маленькие сцены со скриптами `game/door.gd`, `button.gd`, `item.gd`; двор вставляет их и задаёт `locked`, `target`, `label` корню экземпляра), `room.json` (комната: пол 8×8, четыре стены, лампа, камера, скрипт). Порядок сборки: сначала `car.json`, `door.json`, `button.json`, `key.json`, потом `yard.json` и `car_test.json`, которые их вставляют. Операция `instance` принимает и `.glb` (glTF): редактор импортирует модель как сцену, `car.json` ставит `res://assets/kenney/racing/vehicle-truck-red.glb` узлом `Model`, `yard.json` расставляет домики и деревья из `assets/kenney/city/`; свойства корня экземпляра (`position`, `rotation_degrees`, `scale`) задаются как обычно; `"script": "res://game/prop.gd"` делает модель твёрдой (формы столкновений по мешам), `"solid": false` — просто картинкой. В каждом записана фраза человека (`phrase`), блок `scene` и `ops`; `scene apply` берёт из файла только `ops`, `scene build` — всё.

Папка `tools/` помечена файлом `.gdignore`: редактор её не сканирует и не компилирует, поэтому учебный сломанный скрипт лежит там как `examples/yard_broken.gd.txt`.
